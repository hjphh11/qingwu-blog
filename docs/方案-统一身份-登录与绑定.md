# 统一身份：评论系统的登录与绑定（方案 v1）

> 2026-11-12 · 状态：待评审，未落地
> 关联：`docs/方案-后台-admin.md`（旧的两级登录）、`worker/migrations/0013_admin.sql`

## 0. 一句话

把「访客每次手填身份 + 本机 `delete_token`」和「管理员密码 + 邮箱验证码」合并成**一张 `accounts` 表**：
**邮箱是唯一锚点**，登录方式（邮箱验证码 / GitHub）只是挂在账号上的「身份」，留言通过 `account_id` 归属。

---

## 1. 现在的三个洞

| 洞 | 现象 | 代价 |
| --- | --- | --- |
| **身份不持久** | 归属靠 `localStorage` 里的 `delete_token` | 换设备、清缓存、换浏览器 = 永久失权；且只能删不能改 |
| **身份不唯一** | 每次留言重填名称/邮箱/网址 | 同一个人可换任意名字，限流（ip_hash）与审核拿不到「人」这一维；署名可随意冒充 |
| **两套认证** | `admin_users` / `admin_sessions` / `admin_codes` / `admin_attempts` 与访客体系无关 | 验证码冷却、会话时长、锁定策略全都要维护两份，改一处漏一处 |

现状速查：
- 留言：`POST /friends-board`，落 `comments`（`post_slug='friends'`），存 `email` 明文 + `email_hash`(md5) + `delete_token`。
- 删除：`DELETE /friends-board/:id`，只认 `delete_token`（见 `friends-board.ts:567`）。
- 点赞：`friend_likes` 主键 `(comment_id, visitor)`，`visitor` = sha256(salt|ip|ua) 前 16 位。
- 后台：PBKDF2-SHA256(150k) → 6 位邮箱验证码 → HttpOnly cookie 30 天；`/admin` 与 `/api/admin/` 先过 nginx Basic Auth。

## 2. 数据模型（`0023_accounts.sql`）

```sql
-- ① 账号：一个「人」，邮箱唯一锚点
CREATE TABLE IF NOT EXISTS accounts (
  id            INTEGER PRIMARY KEY AUTOINCREMENT,
  email         TEXT    NOT NULL UNIQUE,   -- 存 lower(trim(x))，不用原样
  email_hash    TEXT    NOT NULL,          -- md5(lower(trim(email)))，与 avatar.ts 同源
  display_name  TEXT,                      -- 默认署名，可改
  site_url      TEXT,
  avatar_url    TEXT,
  role          TEXT    NOT NULL DEFAULT 'visitor',  -- visitor | admin
  pass_hash     TEXT,                      -- 只有管理员有；访客恒 NULL
  salt          TEXT,
  iterations    INTEGER NOT NULL DEFAULT 150000,
  created_at    INTEGER NOT NULL,
  last_seen_at  INTEGER,
  status        TEXT    NOT NULL DEFAULT 'active'    -- active | muted | banned
);
CREATE UNIQUE INDEX IF NOT EXISTS idx_accounts_email_hash ON accounts(email_hash);

-- ② 登录方式：一个账号挂多条，邮箱 + GitHub 都算
CREATE TABLE IF NOT EXISTS account_identities (
  id           INTEGER PRIMARY KEY AUTOINCREMENT,
  account_id   INTEGER NOT NULL,
  provider     TEXT    NOT NULL,   -- 'email' | 'github'
  uid          TEXT    NOT NULL,   -- email 地址 / GitHub 数字 id
  meta         TEXT,               -- JSON：login / avatar_url / html_url
  created_at   INTEGER NOT NULL,
  last_used_at INTEGER,
  UNIQUE(provider, uid)            -- 一个 GitHub 只能挂一个账号
);

-- ③ 会话：取代 admin_sessions，访客与后台共用
CREATE TABLE IF NOT EXISTS auth_sessions (
  token_hash TEXT    PRIMARY KEY,  -- 只存 sha256(token)
  account_id INTEGER NOT NULL,
  kind       TEXT    NOT NULL,     -- visitor | admin
  created_at INTEGER NOT NULL,
  expires_at INTEGER NOT NULL,
  ip_hash    TEXT,
  ua         TEXT
);
CREATE INDEX IF NOT EXISTS idx_auth_sessions_acc ON auth_sessions(account_id, expires_at);

-- ④ 验证码：取代 admin_codes。账号还不存在时 account_id 为空、只记邮箱
CREATE TABLE IF NOT EXISTS auth_codes (
  id         INTEGER PRIMARY KEY AUTOINCREMENT,
  email      TEXT    NOT NULL,
  account_id INTEGER,
  code_hash  TEXT    NOT NULL,     -- sha256(code|salt)
  purpose    TEXT    NOT NULL,     -- login | bind | change_email
  sent_at    INTEGER NOT NULL,
  expires_at INTEGER NOT NULL,
  tries      INTEGER NOT NULL DEFAULT 0,
  used       INTEGER NOT NULL DEFAULT 0
);
CREATE INDEX IF NOT EXISTS idx_auth_codes_email ON auth_codes(email, sent_at DESC);

-- ⑤ 登录尝试：取代 admin_attempts（按 IP 限流）
CREATE TABLE IF NOT EXISTS auth_attempts (
  id      INTEGER PRIMARY KEY AUTOINCREMENT,
  ip_hash TEXT    NOT NULL,
  ts      INTEGER NOT NULL,
  ok      INTEGER NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_auth_attempts ON auth_attempts(ip_hash, ts DESC);

-- ⑥ 留言归属 + 点赞归属
ALTER TABLE comments ADD COLUMN account_id INTEGER;             -- 可空：迁移前的孤儿
CREATE INDEX IF NOT EXISTS idx_comments_account ON comments(account_id);
ALTER TABLE friend_likes ADD COLUMN account_id INTEGER;         -- 登录后按账号去重
```

**为什么 `pass_hash` 放在 `accounts` 而不是做成 `identity(provider='password')`**：管理员只有一种密码，
多一层表只多一次 join；访客那一列永远是 NULL，零成本。

**为什么不用 `email` 明文做主键**：需要保留 `email_hash` 给 Gravatar 与前台头像（已有约定：列表只返回哈希）。
两者同源，迁移时互为校验。

## 3. 邮箱是唯一锚点（"同一个邮箱账号互通"）

所有能拿到**已验证邮箱**的入口，统一走这一段：

```
拿到 email（已验证）
  ├─ 按 email 查 accounts
  │    ├─ 命中 → 登进这个账号（把本次 provider 记到 account_identities，若无）
  │    └─ 未命中 → 建账号 + identity(email)
  └─ 写 auth_sessions，发 cookie
```

三条绑定语义，必须写死，否则后面一定乱：

1. **未登录点 GitHub，而 GitHub 主邮箱已存在** → **直接登进那个账号**，不新建。页面提示「已并入 xxx@…」。
   这是「互通」的核心，**不是错误**。
2. **已登录点「绑定 GitHub」，该 GitHub 已被别的账号占用** → `409`，提示「这个 GitHub 已绑定到另一个账号」。
   不自动合并（合并要另做「账号合并」流程，见 §9 未来）。
3. **已登录点「绑定 GitHub」，GitHub 邮箱 ≠ 当前账号邮箱** → 允许绑，**不改主邮箱**。
   改主邮箱只能走 `purpose='change_email'` 的验证码，两步确认。

解绑规则：**至少留一种身份**；`role='admin'` 的账号不允许解绑 `email`（否则找不回）。

## 4. 接口（`worker/src/auth/*`）

对外全部走 `/api/auth/*` → nginx `location /api/` 去前缀 → Worker `/auth/*`。
**nginx 零改动**（`/api/admin/` 才带 Basic Auth，`/api/auth/` 不会被那道拦）。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/auth/email/start` | `{email, turnstile}` → 发 6 位码。**无论账号是否存在都返回同样的 `{ok:true}`** |
| POST | `/auth/email/verify` | `{email, code}` → 建号或登入 + `set-cookie`；返回 `{account, identities}` |
| GET | `/auth/me` | 当前账号（邮箱打码 `145****@qq.com`）+ 已绑定身份 + 我的留言数 |
| POST | `/auth/logout` | 删会话 + 清 cookie |
| GET | `/auth/github/start` | 302 到 GitHub，带随机 `state`（存 10 分钟 cookie） |
| GET | `/auth/github/callback` | 换 token → `/user` + `/user/emails` → 走 §3 锚点逻辑 |
| POST | `/auth/bind/github/start` | 已登录态绑定，state 里带 `bind:<account_id>` |
| DELETE | `/auth/identities/:provider` | 解绑（末位身份拒绝） |
| PATCH | `/auth/profile` | `{display_name, site_url, avatar_url}` 存成默认档案 |
| GET | `/auth/my-comments` | 我的留言（含 `status`），供「我的留言」面板 |

改动既有接口（不给新路径，避免前台两套调用）：
- `POST /friends-board`：带 cookie 时忽略前端传的 `name/url/avatar`，**以档案为准**（前端仍可传"本条改用这个署名"）；
  `email` **不再落明文**（`account_id` 非空时 `email=NULL`），通知走 `accounts.email`。
- `DELETE /friends-board/:id`：判定顺序 = `account_id` 匹配 → `delete_token` 兜底 → 403。
- `POST /friends-board/:id/like`：已登录按 `account_id` 去重，未登录沿用 `visitor`。

## 5. 一次性迁移（`worker/scripts/migrate-accounts.mjs`）

**幂等 + 先 dry-run**。默认只打印，`--apply` 才写。

1. 分组键 `email_hash`（= `md5(lower(trim(email)))`，与 `src/lib/avatar.ts:112` 完全一致，能直接对上）。
2. 每组建一个 `accounts`：
   - `email` ← 组内最新一条非空 `email` 原文，lower+trim；
   - `display_name` ← 该邮箱**最近一条**留言的 `author`；
   - `site_url` ← 该组出现次数最多的 `author_url`（并列取最新）；
   - `avatar_url` ← 同上规则的 `avatar`。
3. `UPDATE comments SET account_id=? WHERE email_hash=?`
4. **孤儿**（`email` 与 `email_hash` 都为空）：`account_id` 留 NULL，**保留 `delete_token`**，
   前台照常显示、作者仍能自删。这条必须留着 —— 它是「匿名留言」唯一的活口。
5. 迁移**不改任何行内容**，只补 `account_id`；前后条数必须相等，脚本末尾打印 `before/after` 校验。

> ⚠️ 生产执行时机：`git pull` → build 不停服 → `systemctl stop qingwu-api` → 跑脚本 → `start`。
> 跑之前务必 `cp /data/qingwu/data/qingwu.db{,.bak-$(date +%F)}`。

## 6. 后台：两边统一成一套身份

- `getAdmin()` 改为：读 `auth_sessions` → join `accounts` → 要求 `role='admin'`。
- `admin_users` 直搬成 `accounts(role='admin')`：`pass_hash / salt / iterations` 字段名不变，脚本一列对一列。
- 后台登录第一步仍是「账号 + 密码」，第二步的验证码改走 `/auth/email/*`（`purpose='login'`）。
- **过渡期双读**：新表里查不到管理员时，回落旧 `admin_sessions`；开关 `AUTH_LEGACY_ADMIN=1` 控制。
  原因很实际 —— 一次性切断如果哪里写错，**后台就进不去了**，而它偏偏是修错的地方。
- nginx Basic Auth **保留不动**（第一道防线，与身份体系无关）。
- ⚠️ 已有的坑不变：往 `auth_sessions` 插 sha256 造临时会话在生产行不通（workerd 的 sqlite 看不到外部写入），
  改密码/造会话都必须重启 `qingwu-api`。

## 7. 安全清单

| 面 | 做法 |
| --- | --- |
| 验证码 | 6 位数字、只存 `sha256(code|salt)`、5 分钟有效、单码 5 次、用后即焚 |
| 发信频率 | 同邮箱 60s 冷却 + 24h 内 ≤10 封；同 IP 1h ≤10 封；中继按 §9 的风险单列 |
| 人机验证 | 发码接口挂 Turnstile（复用 `verifyTurnstile`），仅此一处 |
| 枚举 | 发码一律 `{ok:true}`；`verify` 失败只说「验证码不正确或已过期」 |
| 会话 | `HttpOnly; SameSite=Lax; Secure; Path=/`，访客 30 天；只存 token 的 sha256 |
| CSRF | `SameSite=Lax` + 所有写接口校验 `Origin`（`originAllowed` 已有） |
| OAuth | `state` 随机 32 字节存 cookie、10 分钟、回调即焚；**不信任** GitHub 返回的未验证邮箱 |
| 暴力破解 | `auth_attempts` 15 分钟内失败 15 次锁 15 分钟（沿用现值） |
| 冒充 | `display_name` 全站唯一化（大小写不敏感）；已存在的名字别人不能再用 —— 可选，见 §10 待定 |

## 8. UI（评论区）

形态：**不新开页面，登录是留言板里的一个轻弹层。**

- **未登录**：表单顶部一行 `已填过？用邮箱登录，回访不用再填 · GitHub`。
  点「登录」弹层：邮箱 → 6 位码（6 个格子，自动跳格、粘贴整串自动分配、`Esc` 关闭）→ 回来表单已填好档案。
- **已登录**：表单头部变成 `以 ⟨头像⟩ 名字 留言`，右侧 `我的留言 · 退出`。
  三个输入框折叠成一行可展开的「改一下署名 / 站点」。
- **我的留言**：抽屉列出自己的留言（含「等我看看」徽章），可删可改；不跳页。
- 视觉沿用现有 `glass-card` + `crimson` 强调 + 12px 圆角，**不引入新的设计语言**；≤640px 弹层变全屏底部抽屉。
- 后台登录页**不改视觉**，只把「验证码」那一步换共用组件逻辑。

## 9. 分阶段落地

| 阶段 | 内容 | 可独立上线 |
| --- | --- | --- |
| 0 | `0023` 迁移 + `worker/src/auth/` + 迁移脚本 dry-run | ✅ 纯后端，前端不动 |
| 1 | 访客登录弹层 + 留言归属 + 「我的留言」（**不开「必须登录」**） | ✅ 老访客无感 |
| 2 | GitHub OAuth（含绑定/解绑） | ✅ 单独开关 `GITHUB_OAUTH` |
| 3 | 后台切统一会话（双读过渡 1~2 周后再删旧表） | ⚠️ 先在生产验证再删 |
| 4 | 开 `REQUIRE_LOGIN=1`（未登录只读） | ⚠️ 见风险 3 |

**风险与对策**

1. **GitHub 大陆不稳** → 邮箱通道永远可用；GitHub 只做「可选绑定」，且登录按钮不放在主路径第一位。
2. **发信量** → 本地中继是自建的，但每日 04:00 才补发死信；登录码**不走 outbox 重试**（过期了重发更合理），
   失败直接告诉访客「信没发出去，换个方式」。需先核 `relay.py` 的日限额。
3. **`REQUIRE_LOGIN` 会掉留言量** → 默认关。开之前先看两周数据：`登录留言 / 匿名留言` 的比例。
   这也是为什么 §5 第 4 条要保留孤儿留言的删除凭证 —— 收口之后仍有回头路。
4. **账号合并**（同一人两个邮箱）→ 本期不做，留 `docs` 一句话：需要「登录后加第二个邮箱并合并」的独立流程。

## 10. 已拍板的三个决定（2026-11-12）

1. **`REQUIRE_LOGIN` 默认开** —— 未登录只能读；提交返回 `401 login_required`。
   想退回「游客也能发」：把 `wrangler.toml` 的 `REQUIRE_LOGIN` 改成 `off` 重启即可，不用改代码。
   ⚠️ 身份表还没迁移时后端会**放行**（`currentAccount()` 返回 `undefined`）——
   一次没跑完的迁移不该把整个留言板锁死。
2. **`display_name` 不做唯一** —— 靠 `account_id` 区分，重名只在有人投诉时人工处理。
   理由：唯一化会让「清吾」「小吾」这类常用名被抢占，而冒名在这个规模的站上不是主要威胁。
3. **GitHub OAuth 一次做完** —— 不留到阶段 2，与邮箱通道同批上线（`GITHUB_CLIENT_ID` 配了才显示按钮）。
