重写整站的时候，有两件事看起来最不「设计」，但做完之后受益最久：一是把那个已经长到两千多行的 `global.css` 拆开，二是把字体从 13MB 砍到 957KB。

这两件事都有个共同点：**做完之后产物应该和之前完全一样**。不一样就说明手抖改了东西。所以它们都得先能被验证。

## 拆，但不能拆歪

一开始它就是一个文件。写的时候很顺手，所有东西都在手边：变量、重置、版式、卡片、正文排版、特效、动画。等到要找一条规则时，就得靠搜索，而且很难判断「这条到底该不该在这里」。

重写时我按**职责**把它切成了九份：

```css
@import "./tokens.css";   /* @theme 变量，必须最早 */
@import "./fonts.css";    /* 子集字体的 @font-face */
@import "./base.css";     /* 重置 */
@import "./layout.css";   /* 版式骨架 */
@import "./ui.css";       /* 可复用零件 */
@import "./prose.css";    /* 正文排版 */
@import "./effects.css";  /* 氛围与特效 */
@import "./emis.css";     /* 立绘 2.5D */
@import "./motion.css";   /* 揭示 / 暂停 / 降级，必须最后 */
```

关键在于：**这个顺序就是层叠顺序**，它不是随便排的目录结构，而是有约束的。

`tokens.css` 必须最早，因为后面所有文件都可能引用它定义的变量。`motion.css` 必须最后，因为里面有一条救命规则：

```css
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    animation-play-state: paused !important;
  }
}
```

带 `!important` 的兜底必须盖在最后面才生效。同理，`motion.css` 里刻意**不带 `@layer`** —— 一旦包进 layer，它的优先级反而会掉到普通规则之下。

这条「顺序即层叠」我直接写在了 `index.css` 顶部的注释里。半年后回来改的人（大概率还是我自己）第一眼就能看到，而不是从某条不生效的规则开始猜。

## 怎么证明「拆完没变」

拆文件最容易出的不是设计错误，是**手滑**：少抄一个选择器、顺序调错一格、合并时吃掉了两个花括号。

所以我写了 `scripts/verify-css-split.cjs`，思路很笨但很有效：把原文件留着当对照，两边都做同样的规范化，然后逐字符比较。

```js
const strip = (s) => s.replace(/\/\*[\s\S]*?\*\//g, '').replace(/\s+/g, '');

const A = strip(unwrapLayer(strip(origRaw)));
const B = strip(unwrapLayer(strip(parts.join('\n'))));

if (A === B) {
  console.log('✅ 两者完全一致 —— 拆分无损，规则顺序与内容都保住了');
}
```

`strip` 去掉注释和所有空白（包括换行），`unwrapLayer` 把 `@layer components { ... }` 的最外层壳子解掉 —— 因为拆完之后每个文件都各自带一层 `@layer`，拼接起来和原来一个大 layer 在结构上不同，但**解包后的规则序列应该完全一致**。

跑出来两个长度相等、字符串相等，才敢提交。这比「打开页面看着没问题」强得多：视觉效果只覆盖你恰好看到的那些页面和断点。

这一步也顺手回答了一个常见疑问 —— 拆文件会不会让 CSS 变多？不会。打包器还是把它们合成一个 `Layout.xxx.css`，最终产物 94KB 左右，和拆分前同量级。

## 版心只能有一个来源

拆完之后我干的第一件事，是把「宽度」这件事收成一个变量：

```css
--shell-max: 1080px;
--shell-gutter: clamp(1.25rem, 0.6rem + 2.2vw, 2.5rem);
```

导航、正文、页脚三者共用这两个值。用法只允许两种：直接套 `.page-shell` 容器，或者自己用 `var(--shell-max)` 加同样的 gutter 外层包一层。

**绝对不要写第三个数。** 这条是踩出来的：某次给 `.page-shell` 顺手加了 `max-w-5xl`，容器立刻又被居中了一次，正文左缘相对导航横跳了 44px —— 页面本身没有报错，但一眼就能看出「歪了」，而且说不清歪在哪。

还有一条纪律：窄栏要下沉到内层。给外层容器加窄栏，等于让它重新居中一次，左缘又开始跳。宽度是横轴的「唯一真理」，只该在一个地方被决定。

## 时长也别写裸数字

同理，动画时长收成了梯队：

```css
--dur-micro: 180ms;      /* 悬停、按下 */
--dur-state: 340ms;      /* 展开、收起 */
--dur-move: 560ms;       /* 位移、FLIP 归位 */
--dur-cinematic: 900ms;  /* 场景过渡 */
```

组件里不许出现 `0.2s`、`200ms` 这种裸数字，一律按语义挑一档。配了个 `scripts/check-tokens.mjs` 扫漏网的，改完跑一遍，比人眼靠谱。

有意思的是，这个约束反过来改进了设计：当「时长」只有四档可选时，你会被迫想清楚这个动效到底是「反馈」还是「位移」，而不是凭手感填一个 250ms。

## 字体：从 13MB 到 957KB

字体是另一个体积黑洞。

最初用的是 `@fontsource` 的中文字体。它按 `unicode-range` 把字体切成一个个分片，浏览器按需下载 —— 听起来很聪明，实际是全站要准备 **174 个文件、约 13MB**。

真正的问题不是总量，而是**中文字体的分片策略对「只用一个字体显示几十个汉字」这件事毫无意义**。站酷小薇用来做标题，马善政只用在开屏问候、空态提示和 404 的那个「?」上。

所以我写了个 `scripts/subset-fonts.py`：

1. 把 92 个中文字片**合并**成一个完整字库（拉丁分片不参与，否则字形会重复）
2. 按「这个字体实际要渲染哪些字」分别裁剪
3. 只输出 woff2（现代浏览器不需要 woff 了）
4. 直接生成 `fonts.css` 的 `@font-face`

结果：两个文件，共 **957 KiB**。

```css
@font-face {
  font-family: "ZCOOL XiaoWei";
  font-style: normal;
  font-weight: 400;
  font-display: swap;
  src: url("/fonts/zcool-xiaowei-subset.woff2") format("woff2");
}
```

其中站酷小薇 947 KiB，马善政只有 **9.8 KiB**。差了将近一百倍，原因在字集。

## 两种字体，两套字集

这是整个字体方案里最关键的一件事：**它们不该共用一个字表。**

站酷小薇挂在标题、数字和**访客城市名**上。城市名来自运行时 IP 定位，可能是任意地名，构建期根本扫不到。所以它必须带上 GB2312 一级常用字（3755 个）兜底 —— 否则「攀枝花」这类地名会直接出方框。

```python
def gb2312_level1() -> str:
    """GB2312 一级汉字（3755 个），按区位码生成，不依赖外部字表文件。"""
    out = []
    for hi in range(0xB0, 0xD8):
        for lo in range(0xA1, 0xFF):
            try:
                out.append(bytes([hi, lo]).decode("gb2312"))
            except UnicodeDecodeError:
                continue
    return "".join(out)
```

马善政只用在三处固定文案上，那就没必要背常用字，字集按文案精确生成 —— 总共二十几个字。

代价是它变脆了：**改文案必须同步改脚本里的 `HAND_TEXTS`**。

```python
HAND_TEXTS = [
    "欢迎来到清吾的小屋",
    "这里还很空 ~",
    "音乐馆还没开张 ~",
    "友链还没开张 ~",
    "?",
]
```

漏改就会出现「新加的几个字变成系统字体」这种特别难查的现象 —— 页面不报错，只是那几个字的字形突然不一样了。所以我在这份数组上直接标了出处（哪个文件、哪一行用的），并且约定改开屏/空态/404 的文案时一起改。

另外，`public/fonts/*.woff2` 是**进仓库**的。构建平台没有 Python，字体得跟着代码一起走，不能指望部署时现生成。

## 小结

这两件事都不是「技术难点」，而是**纪律**：

- 分层要有顺序约束，而且约束要写进文件顶部
- 拆完必须能逐字节验证，不靠肉眼
- 宽度、时长这类「横轴与节奏」只能有一个来源
- 字体的字集要按用途分，别为了一句问候打包 3755 个字

做完之后最大的变化不是加载快了，而是**改东西时不再犹豫该写在哪**。这大概就是「结构」的真实价值。
